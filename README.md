# 展馆团体活动名额采集服务

这是一个用于展馆团体活动名额的本地数据采集与归档服务。当前版本从仓库自带的合成来源记录读取一页数据，经过字段规整后写入进程内目录；来源内容和规整后的记录保留独立边界，便于在不访问外部系统的情况下复现采集过程。

## 运行

需要 Node.js 20 或更高版本，不需要安装第三方依赖。

```sh
npm test
npm run build
node src/pipeline.mjs
```

测试使用项目内的合成记录；执行不需要网络、凭据或外部服务。

## 撤场与短暂失败的区分

采集流程严格区分两类情况，避免把学生安排到无效时段，也避免一次请求失败就清空仍有效的活动：

- **正式撤场**：来源页在记录上明确给出撤场终态（`withdrawn`、`cancelled`、`canceled`、`closed`、`撤场`、`已取消`、`已撤场`），规整后统一为内部 `cancelled` 并打上 `withdrawn: true` 标记。记录仍保留在全量归档 `store.list()` 中可审计，但不会出现在 `store.listActive()` 的有效活动视图里。
- **短暂读不到**：来源读取、解析或规整抛出异常（如 `TransientSourceError`）时，本轮返回 `status: 'unavailable'` 且完全不写入 store，此前归档的有效活动原样保留。
- **记录从页中消失不等于撤场**：可能只是分页或暂时不可读，流程不会据此删除或标记旧记录；只有来源显式给出终态才算撤场。
- **名额调整**：来源记录可携带 `capacity`，随更新的 `revision` 一起落库；陈旧修订号无法覆盖较新的记录（包括用撤场终态回灌的情况）。

`collect()` 成功时返回 `status: 'ok'`，来源不可用时返回 `status: 'unavailable'` 并附带 `error`。
